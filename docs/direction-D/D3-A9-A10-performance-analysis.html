Replacement one-hour soak passes - 23 July 2026

The diagnosed 48-slot, Torch-8 fix sustains 5,876/s.

Manifest-v2 now replaces finished games while collection remains open, credits the predicted unfinished rows already in active games, and then drains every admitted game before PPO. The selected 32-slot, 32,768-row configuration sustained 5,308 trained transitions/s with 0.33% spread and 13.6% total overshoot.

Decision: pass the A10 operational gate and adopt 48 slots, capacity 288, and Torch 8/2 for the native recipe. The replacement sustained 5,875.53/s for one hour with 98.84% minimum-to-median stability, stable CPU performance and memory, no stall, and a valid checkpoint.
Training-recipe caveat: the confirmed rate uses n_steps=32,768, so PPO updates happen less often and over larger rollout batches than in the earlier arm. This is not learning-equivalent to the frozen smaller-rollout recipe. It requires a new immutable policy generation and bounded learning-quality comparison before campaign use.

The implemented fix

NativeCollector.collect() now estimates unfinished rows in every active game. If those rows are insufficient to reach the target, it admits deterministic replacements into vacant slots. Once the target closes, admission stops and all live games drain under the same frozen policy.

  • Mean policy batch rose from 6.06 to 17.11 rows.
  • Batch-size-1 calls fell from 30.4% to 15.5%.
  • Calls of size 4 or smaller fell from 63.2% to 32.7%.
  • p50 is now 9, p95 is 48, and the measured maximum is 160 rows.

Overshoot control: a reserve factor of 1.30 conservatively values unfinished active games. The naive 1.00 formula passed speed but over-admitted by 43.7%; the selected 1.30/32K arm reduces total overshoot to 13.6% while increasing the median rate.

Exactness: repeated manifests remain byte-identical and uninterrupted, one-stop, and two-stop fresh processes share one complete-state digest.

PPO is the second ceiling

PPO now consumes 12.19 seconds, or 57% of wall time. Increasing the minibatch from 256 to 512 or 1,024 could improve headroom, but it changes gradient updates and therefore the learned policy. The current rate already passes adoption, so do not bundle this into the refill recipe.

Before changing the recipe, two exact-oriented ideas are worth measuring: use normalized logits directly for PPO log-probability and entropy calculations, and test a sparse legal-action head that evaluates only legal rows from the existing weights. The sparse head is mathematically equivalent but may change float rounding because it uses different matrix shapes, so it still needs strict output and resume gates.

What the diagnosis rejected

  • Concurrent live/snapshot forwards: exact outputs passed, but median speedup was only 1.001x against the predeclared 1.10x gate. The prototype was removed.
  • Thermal or EcoQoS failure: active-core performance remained stable and process execution-speed throttling was inactive while throughput declined.
  • Native rule kernels: earlier full-rule measurement was already 7.63x scalar, and current time is dominated by inference and PPO.
  • CUDA immediately: GPU work remains a separate environment and architecture decision. The native CPU configuration has already passed its one-hour operational gate.
