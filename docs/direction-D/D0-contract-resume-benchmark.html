D0: freeze what “same training run” means.

D0 adds three receipts before any lane or tensor work: a canonical scalar-engine trace, an end-to-end A8 benchmark, and a full-state checkpoint that makes a planned stop indistinguishable from uninterrupted training.

Direction D · implementation design
Parent decision: affordable training substrate

Boundary Safe PPO boundaries only.

No partial game, rollout buffer, lane scheduler, policy change, or large learned-policy campaign is part of D0.

01 · Implementation decision

Extend the scalar trainer; do not replace it.

The A8 loop remains the one semantic and performance reference. Resume is an opt-in configuration around that loop. A resumed process rebuilds ordinary A8 objects, validates the checkpoint in isolation, restores every mutable component, restores RNG last, and continues at the next iteration.

Why this shape It exercises the real adopted recipe without introducing a second trainer. D1 can later consume the same checkpoint metadata and environment protocol while the scalar implementation remains available for differential checks.

Deliberate constraint: D0 checkpoints are taken only after a PPO update, snapshot-pool maintenance, milestone callbacks, and iteration logging have completed. Mid-rollout recovery belongs to D1 only if an eight-hour rehearsal shows boundary checkpoints are operationally insufficient.

Load first verifies the receipt bytes, schema, recipe, campaign, source, anchor, codec, required keys, and policy tensor shapes. Only then is a newly constructed training context populated. A truncated, corrupt, stale-schema, or incompatible checkpoint fails without exposing a partially restored trainer.

03 · Scalar semantic receipt

Canonical JSON traces become D2’s oracle corpus.

Each trace row contains the game identity, seat count, round, current phase, yielded decision and legal payload, acting-seat observation, legal-action mask, complete public/private scalar state, deck order, local game RNG state, and a canonical SHA-256 digest. The corpus driver uses deterministic legal actions and generated tracks, so the same source receipt must reproduce byte-identical JSON.

The first corpus covers 2, 3, 4, 5 and 6 seats and every yielded decision kind. It also records engine event phases and terminal ordering. D2 will add tensor-side snapshots and demand zero differences; D0 does not implement a second engine.

04 · D1 seam

Freeze capability and data shapes, not an implementation framework.

reset(game_ids, seeds, seat_counts) -> ready lane identities
ready()                              -> bounded policy-decision rows
observe(rows)                        -> observations + legal masks
step(rows, actions, policy_version)  -> completed samples + ready rows
drain(policy_version)                -> safe boundary + bootstraps
snapshot()                           -> canonical comparable state

The protocol requires stable game/seat identities, a declared policy version, bounded transition accounting, and semantic snapshots. It does not require Gymnasium, multiprocessing, PyTorch tensors, or CUDA; those remain replaceable implementation details.

07 · Exit gates

D1 stays blocked until correctness and baseline stability are both evidenced.

  • Resume equality.
    Policy, optimizer, controller, pool, counters, diagnostics, RNGs and next scheduled work match across all three D0-R arms.
  • Invalid-state rejection.
    Truncated, corrupt, hash-mismatched and recipe/source/campaign-incompatible checkpoints fail before continuation.
  • Corpus coverage.
    2–6 seats, all five decision kinds, engine phase/event coverage and terminal order are present with deterministic digests.
  • Baseline repeatability.
    Three scalar rollout rates have at most 5% relative spread; a median more than 10% outside the prior band is investigated before D1.
  • Engineering gates.
    Focused tests, strict mypy and targeted Ruff pass; the legacy non-resume call remains behaviorally unchanged.
08 · Live status

D0 worked: one training run can now be safely split into blocks.

The result in one sentence. We can stop training at a safe point, close the program, and continue in a new process without changing what the run learns next. The current training speed is also stable enough to use as the reference for D1.

This stage was mainly about trust, not speed. D0 does not make training faster by itself. It gives the future faster implementation a reliable “answer sheet” and proves that a long run can be divided into practical blocks without quietly becoming a different run.
