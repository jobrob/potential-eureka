Small runtime wins, and tests worth simplifying

7 September 2026 · Current source revision 73c07fdd35a3c07b38e6a601e85bec4364080b46. Existing uncommitted user changes were preserved.

The clearest cleanup is in the tests. Two search tests duplicate the implementation they claim to check, three other test pairs repeat identical checks, and a default-worker test runs entire races without actually proving serial execution. Runtime opportunities also exist, but the measured gains here are modest.

The original review was followed by implementation at the user’s request. Probes and evidence are under .scratch/performance-review-2026-09-07/. No training campaign was run.

The native collector delays observations for forced moves; policy inference avoids redundant copies; evaluation skips rollout allocation and transition rewards using the existing race driver. Checkpoint compatibility has one shared helper in training.py, with the old exception import retained for callers.

The duplicated horizon tests now have one independent one-round reference and an explicit depth assertion. Three other duplicate pairs were consolidated. Worker-default dispatch uses stubs, the two real multiprocessing comparisons are marked slow, and metadata tests no longer train models. The value-loading integration test uses a saved random-weight model.

Retained: worker determinism, optimized/reference equivalence tests, specialized checkpoint behavior, and the vector modules required by native conversion. Experimental backend deletion and broader inference redesign were not recommendations to implement.

Performance opportunities

1. Delay observation creation until a move needs a policy decision — Implemented

Small change; high confidence that it removes wasted work; limited confidence in the exact speed gain.

src/heat/ml/native_env/collector.py:333 creates an observation before checking the legal-action mask. If only one action is legal, the observation is discarded. Move observation creation below that check. The source boundary is the native collector; the native rules and sampling algorithm need no change.

A temporary version produced identical rollout tensors, episode returns, NumPy random state, and collector continuation state. Both versions produced 6,502 actual rows from a 4,096-row target. Median collection time was 1.170 seconds → 1.128 seconds: about 3.7% higher throughput, or 3.6% less elapsed time.

There were three alternating measured pairs after warmup. The samples overlap and baseline timing drifted, so this is a promising small optimization, not a reliable prediction of training speed. A full training update was not timed.

2. Avoid training-buffer allocation when evaluation only needs the race outcome — Implemented

Measured opportunity; medium confidence; keep the game-playing behavior shared.

src/heat/ml/selfplay/eval_harness.py:344 runs a training collector for each learned-policy evaluation race. multiseat.py:317 allocates rollout arrays for every seat, including scripted opponents whose arrays stay empty. Evaluation then uses the final race state rather than those training arrays.

A policy-backed version of the existing scripted race runner took 0.406 seconds instead of 0.446 seconds across six races: about 9.9% higher throughput, or 9.0% less time. Final game-state hashes and Torch random-state hashes matched. The existing route allocated 23.16 MB of rollout arrays in total across the six races; this is cumulative allocation, not peak memory.

Use a small shared race-driving path or explicit outcome-only mode. Do not introduce another copy of the rules. Before adopting it, also verify truncation, stateful opponents, and supported devices; this probe used CPU, a random policy, a weak heuristic, and two/six-seat games.

3. Remove definite extra copies before redesigning inference — Implemented

Confirmed redundant operation; end-to-end benefit unmeasured.

src/heat/ml/native_env/coordinator.py:184 uses ready.legal_masks[indices].copy(). Integer-array indexing already produces an independent array, so the explicit copy copies the same masks again. The later astype(np.float32) calls also copy float32 outputs by default; consider copy=False where dtype conversion must remain supported.

The earlier 5 September profile identified coordinator dispatch as a substantial collection cost. I rechecked the current code but did not rerun that profile or measure these copy changes. Start with these simple removals, then measure grouping or distribution work separately. Preserve frozen keyed sampling, action legality, policy-version checks, and value-only rows. Broadly disabling validation is not justified by this review.

Tests that should change

4. Replace the duplicated horizon-zero reference — Implemented

Highest-priority test finding: confirmed by deliberately introducing a wrong behavior.

tests/test_search_agent.py:209 and tests/test_search_agent_learned.py:287 contain the same test body, each expanded over two leaf-value modes. Their reference helpers call agent._score_plan(), which the real selection path also calls. The claim that this is an independent one-round simulation is therefore inaccurate.

In a temporary process-only mutation, I replaced rounds = max(1, self.horizon) with rounds = 2. All four comparison cases still passed. Both sides agree on the same broken scorer. This demonstrates a gap in these four cases, not that the entire search suite misses the change.

Keep one owner for the two leaf modes and replace its reference with an independently driven single forced round, or a focused assertion on the actual number of rounds simulated. Retain the separate learned-value tests. Sharing the existing reference helper alone would reduce duplication without repairing the coverage gap.

The audit compared parsed test bodies, then checked the candidates manually. These duplicates are cheap; removing them primarily reduces maintenance noise, not suite runtime.

6. Test the worker default without generating whole races — Implemented

tests/test_c7_throughput.py:134 deletes the workers argument, generates a dataset, and only checks that it has rows. It took 3.91 seconds. A changed default of four workers could still satisfy that assertion, despite the test being named test_workers_default_is_serial.

Exercise the actual dispatch branch with stub game results and assert that no process pool is used when the argument is missing. Do not merely copy the default expression into a test. Keep the real serial-versus-parallel output comparisons: they protect deterministic dataset generation.

The solo and two-player parallel tests took 9.41 and 18.70 seconds. They lack the slow marker even though subprocess tests are the documented example of that marker. Marking them slow would move about 28 seconds out of the fast gate while preserving them in the full gate. These durations come from one focused run; startup briefly overlapped a probe, so they are approximate.

7. Stop training a value model to test metadata — Implemented

tests/test_search_agent_learned.py:312 builds a dataset and trains for two epochs to supply a checkpoint fixture. The valid/mismatched metadata cases at lines 343 and 350 only call _validate_value_meta(), which reads the JSON sidecar.

Give those cases tiny sidecar files directly. Keep a separate real save/load/inference integration case. A random-weight checkpoint may also be sufficient for that integration case because it checks loading and legal execution, not learning improvement.

This is unnecessary setup by inspection; I did not time this fixture. Since it is shared with an integration test, splitting the metadata cases alone may not reduce the whole module's runtime.

Production-code maintenance

8. Give checkpoint compatibility one owner — Implemented

src/heat/agents/ml_agent.py:105, search_agent.py:310, and mcts_agent.py:696 repeat the same sidecar lookup and dimension/version comparison pattern.

Extract one small compatibility helper at the existing checkpoint-metadata boundary, retaining useful caller-specific error context. Keep specialized loading, normalization, and value-mode behavior in each agent. This is a maintenance improvement, not a runtime optimization.

Do not delete the entire vector environment as “old code”. The native bridge still imports its state and conversion modules (src/heat/ml/native_env/bridge.py:12, :514). The separate compiled experiment code has verification and benchmark callers. It is a candidate for an explicitly agreed archival decision, not proven dead code.

Likewise, keep the C8/C9/C11 equivalence tests that compare optimized code with older reference behavior, native sampling-order tests, and worker determinism tests. Similar-looking tests can protect distinct contracts. This review found concrete duplication; it does not support wholesale test deletion.

Evidence and limits

  • Baseline verification: 19 focused tests passed in 36.77 seconds. Scope: C7, the horizon-zero groups, the two codec guards, and native A7.
  • Mutation check: all four horizon-zero comparison cases passed with deliberately wrong two-round behavior. The patch existed only in the probe process.
  • Benchmark hypothesis: avoiding unused observation/buffer work should reduce time without changing outputs. Confidence was high in avoiding work, moderate in equivalence, and low-to-moderate in a stable timing benefit. Probe code was confined to scratch files; each measurement took seconds, with visible progress and fixed repetition counts.
  • Clean native timing: the reported native result was rerun after the focused tests completed, replacing an initial overlapping measurement. It used one warmup pair and three alternating measured pairs, an untrained frozen policy, four seats, 48 slots, and 8/2 Torch threads.
  • Review scope: native collection/inference, scalar evaluation, selected search/checkpoint paths, and an exact-body scan across Python tests. This was not an exhaustive line-by-line audit of the entire Python/C++ repository, a full-suite run, a learning experiment, or a production performance guarantee.

Evidence: native benchmark · evaluation benchmark · focused test output · duplicate and mutation audit.

Suggested order: repair the horizon-zero test, consolidate exact duplicates, replace the default-worker test, then adopt the forced-observation change with focused parity checks. Consider outcome-only evaluation next if evaluation is a significant part of the workload. Leave broader inference changes and experimental-backend removal for separate evidence-backed decisions.
