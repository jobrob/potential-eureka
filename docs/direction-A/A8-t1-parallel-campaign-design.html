01 · Design decision

Parallelize outside each game first.

A8 seeds share no mutable training state, and evaluation cells use disjoint deterministic seeds. T1 exploits those two existing boundaries with spawned CPU processes. It does not alter the collector, policy, PPO update, track schedule, reward, or checkpoint-selection rule.

RecommendationBuild one small campaign supervisor plus opt-in process parallelism in the A7 evaluator. Fix Torch to one intra-op and one inter-op thread per training worker so process concurrency does not oversubscribe the machine or silently change the numeric execution shape between benchmark modes.
Primary workload3 × 50k transitions
Compared concurrency1 · 2 · 3 workers

02 · Invariants

Concurrency may change scheduling, never experiment identity.

  • Same resolved recipe. Every worker receives a complete A8Config; it does not inherit changing CLI defaults.
  • Same seed identity. Run dev-t1-R00 always means seed 0, independently of completion order or worker assignment.
  • Same numerical shape. Every benchmark worker sets one Torch intra-op and one inter-op thread before constructing the policy.
  • Same track streams. Training keeps namespace 80008; evaluation keeps its existing per-cell seed derivation.
  • Stable aggregation. Results are sorted by run ID or cell index before hashing and reporting.
  • No comparison-worthy policies. T1 runs are disposable dev-* diagnostics, save no checkpoints, and allocate no policy generation.
  • Opt-in production behaviour. Existing sequential APIs remain the default until the benchmark passes.
Dirty-tree safety.T1 records the current commit and dirty flag in its raw JSON result, but it does not create or modify a learned-policy registry entry because the benchmark policies are disposable and never enter a long-lived comparison.

Use ProcessPoolExecutor with the Windows-safe spawn context. Worker functions, initializers, and argument dataclasses must be module-level and picklable. Do not use lambdas in parallel benchmark opponent maps.

The supervisor prints a start row, a heartbeat at least every 15 seconds while jobs are outstanding, and a completion row for every job. Each benchmark mode has a 15-minute hard deadline. A timeout or worker exception fails the mode and prevents T2 from starting.

The policy hash is over a canonical, name-sorted sequence of state-dict tensor names, dtypes, shapes, and contiguous CPU bytes. It must not depend on torch.save container metadata. Sequential and concurrent execution of a run must produce the same hash, step count, and game count.

The benchmark uses total_timesteps=50_000, n_steps=1024, five PPO epochs, the flat masked policy, no anchor, namespace 80008, and seeds 0–2. It saves no checkpoint and runs no held-out evaluation. These are dev-t1-R00 through dev-t1-R02, not G-numbered policies.

05 · Evaluation cells

Load or copy the policy once per worker, not once per race.

Extend evaluate_policy with keyword-only parallel=False and max_workers=None. The sequential branch remains byte-for-byte equivalent in behaviour. The parallel branch builds the same ordered cell specifications, initializes one CPU policy copy and opponent map in each worker, evaluates cells independently, then restores the original order before constructing EvalReport.

  • CPU only in T1. Reject parallel evaluation on CUDA with a clear error; multiple processes sharing one GPU is a later design.
  • Picklability is explicit. Preflight the policy and opponent map. Name the first unpicklable input rather than silently falling back.
  • One policy copy per worker. Use a process initializer; do not serialize the network once per cell or reload it once per game.
  • Exact report equality. A fixed sequential and parallel call must return equal EvalReport values, including cell order and confidence bounds.
  • Caller RNG neutrality. The parent Torch RNG state remains unchanged, preserving A7’s existing guarantee.

The timing screen uses the registered G0002-R00@1000K checkpoint, two top-level scripted rulers (weak and heuristic_repaired), seats 2/4/6, ten frozen validation tracks, and 20 games per cell. Compare one worker with the fastest accepted count from the training screen. This is evaluation-only, so it does not allocate a new generation.

07 · Focused verification

Prove identity before measuring speed.

  1. Canonical hash. Equal state dicts hash equally; one changed tensor changes the hash.
  2. Campaign equivalence. Two tiny seeded runs at one and two workers return identical run IDs, step counts, game counts, and policy hashes.
  3. Completion-order independence. Artificially delayed jobs still return sorted results.
  4. Parallel evaluation equality. A small two-cell Tiny-Heat grid equals sequential evaluation exactly and preserves the parent RNG state.
  5. Clear invalid-input behaviour. An unpicklable opponent factory and CUDA parallel request fail before workers launch.
  6. Failure propagation. A worker exception identifies its run/cell and produces a failing verdict.
  7. Existing focused suites. Re-run A7 evaluation and A8 Phase-1 tests; no broad new game-rule matrix is required.
